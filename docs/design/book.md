# Book の本文と、図、コード、根拠のつなぎ方

学習用の本文（Book）の置き場所、図とコードの抜き出しの作り方、Zenn への書き出し、旧デッキの内容の行き先の確かめ方を決めた記録です。書き方は [slides/README.ja.md](../../slides/README.ja.md) の「Book」と、プロジェクトのスキル [ims-visual-learning](../../.claude/skills/ims-visual-learning/SKILL.md) にあります。

## 求めること

読者が構成を動かさず、問いに答えず、コードも書かずに、本文と図を読むだけで IMS の仕組みと設計の判断が分かる教材にします。コードと試験は、著者が説明の根拠と例に使います。同時に、次のことを守ります。

- 本文はリポジトリのホストでそのまま読めて、Zenn の Book にも書き出せる。正本は 1 か所で、同じ文章を 2 か所で手で直さない。
- 本文の図は、スライドと同じノード、イベント、状態から描く。スライドの HTML の途中だけに現れる信号を、本文や pptx で落とさない。
- 本文に引くコードは、対象のコードと行のまま一致する。コードが変わったら、検査で分かる。
- 日英で、問い、図、コード、結論が同じである。
- 旧デッキの実習や設問を本文の解説に変えても、その知識の行き先を確かめられる。

## 決めたこと

### 文書ごとの受け持ち

| 文書 | 受け持ち |
| --- | --- |
| Book（`docs/book/{ja,en}/`） | 読むための本文。問いへの答え、図、状態の前後、短いコードとその読み方、適用する範囲、上級の設計の比較 |
| 手順書（`docs/guide/{ja,en}/`） | 動かす人のための参照。構成、コマンド、表示フィルタ、期待する結果、切り分け、片付け、簡略化の表 |
| デッキ（`slides/decks/{ja,en}/`） | 関係、時系列、判断の変化を、図と段階で見せる。本文の該当の章へ案内する |
| 学習単位の記録（`docs/book/units.yaml`） | 単位ごとの問い、構成、章、シーン、コード、試験、条項、根拠の種類、確かめたコードの版 |
| 移行の対応表（[book-migration.md](book-migration.md)） | 旧デッキの内容のまとまりごとの行き先と、その扱い |

Book は手順書を写しません。本文は理由と動作の例を組み立て直し、コマンドの手順は手順書に任せて、そこへリンクします。

### 正本の置き場所

本文の正本は `docs/book/ja/<名前>.md` と `docs/book/en/<名前>.md` の、普通の Markdown です。章の順は `docs/book/book.yaml` の `chapters` に 1 列で書きます。各言語の `README.md` が目次で、入門、中級、上級の読む順を案内します。章の題は、章の最初の `#` の見出しです。

`books/<slug>/` を正本にする案も比べました。Zenn の章はフロントマターを持ち、ディレクトリも 1 つの言語だけのものです。英語の本文を同じ形で置けず、リポジトリのホストで読むときにフロントマターが表として出ます。そこで、正本は言語ごとの普通の Markdown にし、Zenn の形は書き出しで作ります。

Book に独自の記法は足しません。生成器が読むのは、普通の Markdown の 3 つの形だけです。

- `figures/<デッキ>.<シーン>.<段階>.svg` を指す画像は、図です。
- ファイルへのリンクだけの段落のすぐ下のコードブロックは、そのファイルの抜き出しです。デッキと同じ決まりです。
- 同じディレクトリの章のファイルへのリンクは、章へのリンクです。

### 図

図は、デッキのシーンの段階を、pptx と同じ配置の処理（`slides/internal/layout` の `Figure`）で組み、読み物の表示の図と同じ書き出し（`slides/internal/html` の `WriteFigure`）で SVG にします。外側の CSS もスクリプトも使わず、色、線の種類、文字の大きさを、図形の属性に書きます。そのため、画像として単独で開いても、HTML の舞台の段階と同じイベントと状態が出ます。地図は全体を、シーケンス図は最初の段からその段階が描く最後の段までを描きます。段階の番号は描きません。図のそばの文が、シーンの段階の一覧ではないためです。図の下には、線の種類の凡例と、図が何から描いたもの（この実装の動き、仕様の手順、説明のための例）かを書きます。

図のファイルはリポジトリに入れます。リポジトリのホストで本文を読む人に図を見せるためと、図の変化を差分で読めるようにするためです。`go run ./cmd/slides figures` が描き直し、`go run ./cmd/slides check` は、ファイルがいまのデッキから描いたものと 1 バイトも違わないことを確かめます。どの章も使わない図のファイルも誤りにします。

手で描いた図や、レイアウトを別の言語で写す作りは採りませんでした。同じ信号を 2 か所で描くと、片方だけが古くなるためです。

### コードの抜き出し

本文の抜き出しは、デッキと同じ決まりと同じ比べ方（タブを 4 つの空白にし、行末の空白を除く）で、ファイルの行と照らし合わせます。`check` は作業ツリーのファイルと比べます。本文は、それが置かれた版のコードを説明するものとして扱います。Zenn への書き出しは、コードへのリンクを `-repo-url` のコミットに固定し、そのコミットのファイル（`git show`）とも抜き出しを比べます。公開のリンクが、動いていく `main` だけを指すことはありません。

抜き出しが変わらなくても、呼び出す位置や保存の約束が変われば、説明は古くなります。そこで、学習単位の記録に、単位ごとのコードと試験の関数の名前と、確かめたコードの版（`verified`）を書きます。`check` は、名前の関数や型が今もそのファイルにあることを確かめ、`verified` からコードか試験が変わった単位を「読み直す」として挙げます。挙げるだけで、失敗にはしません。コードを変えるたびに文書の作業で止めないためです。読み直して説明がまだ正しければ、`verified` を進めます。

### Zenn への書き出し

`go run ./cmd/slides -repo-url https://github.com/yuu-biz/ims-practice/blob/<コミット> zenn` が、`slides/dist/zenn/` に Zenn の形を書きます。

- `books/ims-practice-book/config.yaml`。`published: false` で、公開しません。章の順は `book.yaml` と同じです。
- 章ごとのファイル。題はフロントマターに移し、`#` の見出しを除きます。章へのリンクは Book の中の章へ、リポジトリのほかのファイルへのリンクはそのコミットの GitHub の URL へ直します。
- `images/ims-practice-book/` の図。Zenn は SVG の画像を受け付けないので（zenn-cli 0.5.14 で、画像は png、jpg、jpeg、webp、gif の 3MB まで）、`node book-images.js dist/zenn` が Chromium で SVG を PNG にします。表紙も、同じ書き出しの `cover.svg` から 500 × 700 の PNG にします。

プレビューは `slides/dist/zenn/` で `npx zenn-cli@0.5.14 preview` です。zenn-cli の版を固定するのは、同じ入力から同じ見え方を確かめるためです。HTML と CSS の埋め込み（Beta）は、スクリプトを実行できず、デッキの HTML をそのまま載せられないので使いません。本文は、静止した図と文章だけで読めるように書きます。

英語の本文も同じ書き出しで `-lang en` を付けて作れます（`books/ims-practice-book-en/`）。英語の Zenn の公開先は決めていません。

### 旧デッキの内容の行き先

旧デッキは勉強会の 1 回分ずつで、実習、振り返り、設問と答えを持っていました。これらを本文の解説や任意の再現の手順に変えると、文字列はデッキから消え、別のファイルへ移ります。`scripts/check_deck_content.py` は、もとは同じデッキに文字列が残っているかだけを調べていたので、移した先を確かめられませんでした。

そこで、移行の対応表に、旧デッキの基準のコミットと、旧デッキの見出しごとの行き先、扱い、行き先に残っているべき語を書きます。検査は、基準のコミットの旧デッキの見出しが、すべて表にあること、行き先のファイルと見出しが実在すること、残っているべき語がその節にあること、旧デッキから消えたリンク、行の中のコード、コードの行、表のセルが、デッキか表の行き先のどこかに残っていることを確かめます。基準のコミットを読めないときは、飛ばさずに失敗します。表に書いたことは人が意味を確かめたもので、検査が意味の同じさまで証明するわけではありません。

## 採らなかったもの

- mdBook、Docusaurus などの文書の生成器。Zenn の形への書き出しと、リポジトリのホストでの読みやすさのどちらにも要らず、依存が増えるため。
- 本文とスライドの全文を 1 つの元データから流し込む作り。本文の論じ方と、スライドの段階の順は違うため。共有するのは、ノード、イベント、状態、根拠です。
- 未制作の動画の欄や、動画へのリンク。

## 確かめていないこと

- zenn.dev の上での見え方。この作業の環境から zenn.dev に届かず、確かめたのは zenn-cli 0.5.14 のローカルのプレビューだけです。
- Zenn の見出しのアンカーと、章をまたぐ `#` 付きのリンクが、zenn.dev の上で同じ位置に届くこと。
