# 学習用の画面と OAM

この記録は信号を見て操作するための学習用の画面と、保守の装置である OAM の設計です。

## 選んだこと

- 学習用の画面「ラボ」は、`ims` コマンドの役割 `lab` にします。Go のサーバーが HEP を受け、状態を HTTP の API で返し、TypeScript で書いた画面を配信します。
- 学習用の画面は HEP で届いたメッセージだけから登録と呼の状態を組み立てます。ノードの内部の状態は読みません。
- 学習用の画面と OAM を分けます。
- OAM のサーバーは、`ims` コマンドの役割 `oam` にします。ラボと同じく、Go のサーバーが HTTP の API を出し、TypeScript で書いた画面を同じ待ち受けで配ります。画面の配り方もラボと同じで、組み立てた資源をイメージのビルドで Go のパッケージに写し、`//go:embed` で埋め込みます。
- OAM の待ち受けは、仕様がポートを決めていないので、ラボの画面と同じ 8080 番にします。どちらも自分のコンテナの中にあり、ぶつかりません。ホストには公開しません。この API はノードの設定を変え、どの加入の資格情報も入った書庫を渡し、そのうえパスワードを求めないからです。ノードの保守用の API を公開しないのと同じ理由です。
- OAM が自分で持つもの、つまり設定の履歴とバックアップは、1 つのディレクトリ（`oam.data_dir`）の下に置きます。Compose では名前付きのボリュームです。設定の項目を 2 つに分けないのは、構成がボリュームを 1 つ渡せば済むようにするためです。
- 障害の注入は学習用の画面から操作します。OAM の画面と API には置きません。
- 各ノードは保守用の API と同じ待ち受けで指標を出します。

## 画面の作り

Go のサーバーと TypeScript の画面にしたのは、ブラウザだけで使えるためと、ラダー図の描画にはブラウザのほうが向いているためです。サーバーは IMS 本体と同じ Go で書きます（[implementation.md](implementation.md)）。この形は決めるべき論点として挙げた案をそのまま採ったものです。メンテナーが別の形を選べば変えます。

HEP で届いたメッセージだけを使うのは、呼の経路から外れた観察役にしておくと、ノードの作りを変えずに済み、ノードを何台に増やしても同じ方法で見られるためです。

学習用の画面は、加入の一覧と UE シミュレータの操作を、HSS の保守用の API と UE の操作用の API へそのまま中継します。自分では状態を持ちません。

Diameter は、HEP3 rev. 37 に Diameter をそのまま運ぶ型が無いため、型 0x38（DIAMETER (JSON)）で JSON に直して送ります。標準の Wireshark は HEP を解析できませんが、元の SIP と Diameter のパケットは今までどおりキャプチャで見られます。

## 学習用の画面と OAM を分ける

| 主題 | 作り |
| --- | --- |
| 受け持ち | 学習用の画面は学習の道具で、信号を見ること、UE を操作すること、障害を起こすことを受け持ちます。OAM は保守の装置で、ドレイン、設定、加入者、退避と復元、警報、トラヒックの統計を受け持ちます。OAM の画面に学習用の画面を組み込む案は採りません。 |
| 画面の名前 | 「ラボ」（Lab）と呼びます。試して観察する場所、という意味です。前の名前の「ダッシュボード」は役目に合わないので変えました。役割、サービス、ホスト名、ディレクトリ、手順書、試験の名前もそろえて、役割は `lab`、画面は `web/lab`、Go のパッケージは `internal/lab`、手順書は `lab.md`、試験は `scripts/e2e-lab.sh` です。 |
| 加入者 | 加入を作る、変える、消すのは運用の操作なので、OAM が受け持ちます。CAT の設定も加入の変更なので、OAM の API と画面にあります。学習用の画面は、HSS が持っている加入の一覧を見せるだけで、書き換える経路を持ちません。登録を取り消す RTR と、変わったプロファイルを送る PPR は、学習者が結果を画面で見たいものです。一方、本物の網でそれが出るのは、運用者が加入を変えたときです。そこで、変更は OAM から行い、画面はその結果を見せます。手順書では、この 2 つを「網が登録を取り消す」と「網が変わったプロファイルを送る」の試しとして、それぞれの見出しの下に置いています。 |
| 障害の注入 | 障害の注入は学習のための試しで、運用の操作ではないので、学習用の画面に置きます。ドレインは運用の操作なので、OAM の側に置きます。Docker のソケットを渡すコンテナは、上書きのファイルで明示したときだけ起動します。IMS のノードを、ホスト固有のネットワーク設定に依存させないためです。 |
| 指標 | 各ノードは、保守用の API と同じ待ち受けで指標を出します。 |

冗長構成での障害注入とドレインの作りは [state-redundancy.md](state-redundancy.md) にあります。OAM の調査は [oam.md](../background/oam.md) にあります。

## 残っている課題

- OAM の画面と API はホストに公開していないので、学習者はブラウザで画面を開けません。加入の操作は、OAM のコンテナの中から要求を送って行います。手順書はそのコマンドを載せています。公開するなら、この API に認証が要ります。
