# この本の読み方

この本は、3GPP の IMS（IP Multimedia Subsystem）を、学習用に実装したこのリポジトリを題材に説明します。IMS は、携帯電話や固定の電話の音声通話、ショートメッセージ、転送のような付加サービスを、IP の網の上で提供する仕組みです。どのノードが何を受け持ち、どの信号で何が決まるかを、図と短いコードで追います。

読むのに、構成を動かす必要はありません。問いに答えたり、コードを書いたりする必要もありません。本文の問いには、その場か続く節で答えます。コードと試験は、著者が説明の根拠として確かめたものです。

## 誰のための本か

IMS を初めて学ぶ人のための本です。IP アドレスとポート、要求と応答のようなプロトコルの基本を知っていれば、読み始められます。SIP や Diameter を知っている必要はありません。必要なヘッダや AVP は、それが仕事をする場面で説明します。略語は [用語集](../../glossary.md) にあります。

Go を読めなくても構いません。本文の結論は、図と文だけで分かるように書いています。コードを読みたい人のために、付録の [コードを読むための Go](go-reading.md) が、抜き出しに出てくる Go の書き方を説明します。

## 3 つの段階

章は 3 つの段階に分かれています。[目次](README.md) は段階ごとに章を並べ、各章は前提にする章を最初に挙げます。

| 段階 | 答える問い | 読むと分かること |
| --- | --- | --- |
| 入門 | このやり取りは何のためにあり、誰が受け持つのか | IMS のノードと、それぞれの仕事。登録と通話で何が決まるか。信号とメディアがどこを通るか |
| 中級 | 条件が変わると、どの判断、状態、メッセージが変わるのか | 仕様のどの条件を、どの関数が判断し、どの状態を変え、どの応答になるか。それを確かめる試験 |
| 上級 | 仕様を守りながら、どこで設計を選ぶのか | 標準が決めていることと、実装や運用が選ぶこと。選べる方法と、それぞれで起きること。この実装の選択と限界 |

入門の章を順に読めば、全体の地図ができます。そのあとは、興味のある分野の中級の章に進んで構いません。上級の章は、前提にする中級の章だけを読めば読めます。

## 章の組み立て

どの章も、最初の数文で問いに答えます。そのあとで、答えの根拠を、仕様の条件、それを判断するコード、変わる状態、その結果の順にたどります。章の終わりには、2 つの節があります。

- **この説明の根拠。** 説明が確かめたコードと試験の名前と、試験が何を確かめているかを書きます。試験が確かめる範囲だけを、試験の結果として書きます。
- **自分で動かす場合。** 同じ流れを自分のキャプチャで見たい人のために、手順書（[docs/guide/ja/](../../guide/ja/README.md)）の節を案内します。読まなくても章は分かります。

本文では、次の 4 つを分けて書きます。仕様が求めること、この実装が選んだこと、この実装が簡略化したこと、説明のための例です。簡略化したことは、手順書の「簡略化していること」の表と、コードの `SIMPLIFIED:` のコメントにもあります。

## 図とスライド

本の図は、リポジトリのスライド（[slides/](../../../slides/README.ja.md)）のシーンを、ある段階で止めて描いたものです。スライドの HTML では、同じシーンを 1 段階ずつ進められます。章とスライドは同じ問いを扱い、章が理由と例外を、スライドが位置と変化を受け持ちます。

図は次のように読みます。

- 地図はノードを升目に置き、信号がどこを通り、誰が判断するかを見せます。シーケンス図はノードごとに縦の線を引き、誰がどの順に話すかを見せます。
- 線の種類はプロトコルを表します。SIP は実線、Diameter は破線、DNS は点線で、HTTP とメディアは別の色です。線のラベルにもプロトコルの名前があります。
- ノードの中の四角は、そのノードが行う判断や処理です。
- 図の下の表は、その段階で注目するメッセージのヘッダ、AVP、値です。
- 図のいちばん下の 1 行が、図の根拠です。

| 根拠の行 | 意味 |
| --- | --- |
| この構成の動きを手順書から描いた模式図です | この実装の動きです。手順書とコードで確かめた順と値を描いています |
| 仕様の手順を描いた模式図です | 仕様が定める手順です。この実装に限りません |
| 考え方を説明するための例です | 説明のために作った例です。値は短く書いたもので、この構成の値ではありません |

どの図も模式図で、キャプチャそのものではありません。

## コードの抜き出し

ファイルへのリンクだけの段落のすぐ下にあるコードは、そのファイルの連続した行を、そのまま写したものです。スライドの生成器が、抜き出しがいまのファイルにあるかを確かめます。説明のために書き換えたものは「擬似コード」と書き、この形では置きません。抜き出しの前後で、入力、見る条件、変えるもの、次に起きることを説明します。

## 例の構成

例は、とくに断らない限り、`deploy/compose` の構成のものです。役割ごとに 1 台のノードが、1 つの Docker のネットワーク（172.28.0.0/24）に並びます。信号は暗号化せず、SIP は 5060 番、Diameter は 3868 番のような標準のポートを使います。

- **UE。** SIM カードの無いソフトフォン型の UE が、Docker のネットワークを通って P-CSCF に届き、SIP Digest で登録して、G.711 で通話します。アクセス網の手順を抜きにして、IMS だけを見るためです。
- **VoLTE。** 携帯電話のように EPC にアタッチし、USIM の鍵を使う IMS-AKA で登録し、音声ベアラを待つ UE は、そう書いた章にだけ出てきます。EPC はスタブです。
- **値。** 電話番号は架空の +1 202 555 01xx、加入者の識別子と鍵は試験用の値、ドメインは `ims.mnc001.mcc001.3gppnetwork.org` です。
