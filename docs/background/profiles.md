# 業界プロファイルと国内標準の調査

この文書は、GSMA のプロファイル（IR.92、NG.114）と国内標準（TTC）が定めることと、この実装との差を調べた記録です。実装は、UE と網の音声の振る舞いが IR.92 と NG.114 の必須の要件を満たすことを目指します。国ごとの標準には、接続先の網ごとの設定として合わせられるようにします。仕様の本文は写しません。要点を言い換えて書きます。節の番号は各文書の見出しの番号です。

## 調べた文書

| 文書 | 版 | 入手先 |
| --- | --- | --- |
| GSMA IR.92 IMS Profile for Voice and SMS | Version 24.0（2026-10-02） | https://www.gsma.com/newsroom/wp-content/uploads//IR.92-v24.0-2.pdf |
| GSMA NG.114 IMS Profile for Voice, Video and Messaging over 5GS | Version 11.0（2026-09-22） | https://www.gsma.com/newsroom/wp-content/uploads//NG.114-v11.0-2.pdf |
| TTC JJ-90.30 IMS 事業者網間の相互接続共通インタフェース | 第 13 版（2025-05-22） | ttc.or.jp。調べた日はサイトが縮小運営中で、Internet Archive の写しで確かめた |

IR.92 の本文には、参照番号（`[n]`）と節の相互参照が、参照一覧や見出しとずれている箇所があります。ここでは仕様の名前と見出しの番号だけを書きます。

## 音声コーデック

| 文書 | 必須のコーデック | 節 |
| --- | --- | --- |
| IR.92 | AMR（全 8 モード）と AMR-WB（全 9 モード）。EVS は、超広帯域か全帯域の通話を提供する端末だけ。G.711 には触れていない。 | 3.2.1 |
| NG.114 | IR.92 と同じものに加えて、EVS がすべての端末に必須。最初の offer に入れる。 | 3.2.1、3.2.2.1 |
| JJ-90.30 | 網間の offer に G.711 μ-law を必ず入れる。移動網どうしの接続では AMR を必ず入れる。ほかは事業者間で取り決める。 | 4.3.5.1.4.1 |

IR.92 の RTP ペイロードの形式は RFC 4867 です。bandwidth-efficient と octet-aligned の両方に対応し、発信するときは bandwidth-efficient を求めます（3.2.5）。ptime は 20、maxptime は 240 です。最初の offer には mode-set を付けない AMR-WB と AMR を入れます（2.4.3.2）。

コーデックの実装は、Go だけで書かれたものが見つかりませんでした。候補は C の実装で、cgo が必要です。

| 候補 | 中身 | ライセンス |
| --- | --- | --- |
| opencore-amr 0.1.6 | AMR の符号化と復号、AMR-WB の復号 | Apache-2.0 |
| vo-amrwbenc 0.1.3 | AMR-WB の符号化 | Apache-2.0 |
| 3GPP の参照コード（TS 26.073、26.173、26.442、26.443） | AMR、AMR-WB、EVS | オープンソースのライセンスは付いていない。利用条件は確かめていない |

特許の扱いはライセンスとは別に確かめる必要があります。AMR と AMR-WB について公開されている資料で読み取れたことは、[codecs.md](../design/codecs.md) に書きました。EVS の実装の方法は、利用条件と特許の扱いを確かめてから決める未決の論点です。

AMR と AMR-WB は、符号化済みのフレームで送り、RTP のペイロードの処理は Go だけで書くと決めました（[docs/design/volte-access.md](../design/volte-access.md)）。製品は cgo を使いません。上の opencore-amr と vo-amrwbenc は、フレームを作る道具だけが使います。

NG.114 の規定の大半は IR.92 と同じ内容です。違いは、EVS が必須になることと、冗長なフレームの受信が必須になることです（3.2.3）。VoNR の構成は 5GC の側で扱います。

IR.92 2.3 の付加サービスの一覧は、付加サービスと MRF の設計に使いました。調査は [mmtel-mrf.md](mmtel-mrf.md) にあります。

## 国内標準（TTC）

TTC の標準は事業者網どうしの接続（NNI）を決めたものです。端末と網のあいだ（UNI）は決めていません。網間接続では、接続先ごとの設定として扱います。国ごとの違いは、3GPP の共通の部分に従い、違いはあとから加えられるようにします。

| 番号 | 題名 | 版 |
| --- | --- | --- |
| JJ-90.30 | IMS 事業者網間の相互接続共通インタフェース | 第 13 版（2025-05-22） |
| JJ-90.31 | キャリア ENUM の相互接続共通インタフェース | 第 6 版（2025-05-22） |
| JJ-90.32 | SIP ドメイン解決のための DNS 相互接続共通インタフェース | 第 4 版（2021-05-20） |
| JJ-90.28 | 緊急通報呼に関する NNI 仕様 | 第 4.5 版（2025-05-22） |
| JJ-90.27 | 着信転送サービス（CDIV）に関する NNI 仕様 | 第 10.0 版（2025-05-22） |
| JJ-90.26 | IMS における SDP メディアネゴシエーション手順 | 第 1 版（2013-05-23） |

JJ-90.30 は TS 29.165 の II-NNI を国内向けに補います。IR.92 の端末の規定と違う点があります。

- セッションタイマーを全セッションに掛け、値は 180 秒から 300 秒のあいだで各社が決める（4.3.4.8）。IR.92 の端末の 1800 秒とは別の規定です。
- 発信者番号は P-Asserted-Identity で運び、tel URI の PAI は 1 つだけにする（4.3.4.1）。
- 100rel への対応は必須で、プリコンディションを使うかは事業者間で決める（4.3.4.2、4.3.4.3）。
- SIP は UDP の 5060 番を必須とする（4.1）。

## 確かめられなかったこと

- JJ-90.30 の 2026 年の改版の有無と、TTC の文書の利用条件。ttc.or.jp に届かなかったため。
- IR.92 Annex C.3 の設定の既定値。表を読み取れなかったため。
- 3GPP の参照コードの利用条件と、各コーデックの特許の扱い。
