# 勉強会のスライド

[English](README.md)

このリポジトリで勉強会を開くためのスライドです。デッキごとに、Markdown に似た小さな書式のテキストファイルが 1 つあります。このリポジトリの生成器 [cmd/slides](cmd/slides/main.go) が各スライドを割り付け、2 つのファイルを書きます。配布して PowerPoint で編集できる pptx と、発表に使う HTML です。どちらも同じ箱を同じ位置に描くので、スライドはどちらでも同じに見えます。

デッキは手順書の内容を繰り返しません。各スライドには、キャプチャで何を見るかを書き、手順書（[docs/guide/](../docs/guide/)）の該当する手順へのリンクを付けます。ラダー図の全体と説明は手順書にあります。

1 から 9 のデッキは、コードの地図、網の地図、信号の見方から始めて、登録、通話、SMS、補足サービス、VoLTE の通話へ進みます。番号は勧める順です。網の地図と、キャプチャとラボのデッキは、登録の前に置きます。これより先のデッキは、どれもこの地図の一部をキャプチャで読み、多くはラボも開くためです。VoLTE のデッキは補足サービスのあとに置きます。VoLTE の手順書は MMTel AS を前提にしていて、VoLTE の通話もすべて MMTel AS を通るためです。0 のデッキはその前に置きます。Go を読んだことがない人のために、このリポジトリで出会う Go の書き方を、コードの抜き出しで説明します。

## 勉強会の進め方

1 つのデッキが 1 回の勉強会で、番号の順に開きます。デッキに発表者ノートはありません。スライドについて発表者が話すことはスライドに書き、演習と「振り返り」の答えはその次のスライドにあります。

- その回の手順書をスライドの横に開いておきます。スライドは読む順番を、手順書は説明とラダー図の全体を受け持ちます。
- 参加者にはリポジトリを手元で開いてもらいます。全員がシナリオを動かすのがいちばんです。難しければ発表者の画面を見せるか、CI の成果物にあるそのシナリオのキャプチャを配ります。
- 条項番号は、手順書が挙げている版のものです。ほかの版を開いている人には、番号が違うことがあると伝えます。

| デッキ | 時間 | 時間の配分 |
| --- | --- | --- |
| 0. Go | 60 分 | 前半の 25 分で「なぜ Go なのか」（3 分）、試験の動かし方、コードの形（10 分）を、後半の 35 分で毎ページで出会う書き方（20 分）と仕様の形をしたパッケージ（10 分）を扱います。演習は 2 人 1 組で、さらに 15 分かかります。ほかの言語でプログラムを書けるが Go は読んだことがない人向けです。Go を読める人は 1 のデッキから始めます。 |
| 1. パッケージ構成 | 45 分 | 信号は読みません。どこに何があるかの地図を作ります。リポジトリの一番上に 3 分、「internal/ を層で見る」に 5 分、2 人 1 組で 1 つの REGISTER をコードで追うのに 10 分を使います。 |
| 2. 網の地図 | 45 分 | ここも信号は読みません。ノードと、その間のインタフェースと、それぞれに流れるプロトコルを見ます。ノードに 10 分、参照点に 15 分、地図のどこをどの回が開くかに 10 分を使います。登録の前に開きます。これより先の回は、どれもこの地図の一部をキャプチャで読むためです。 |
| 3. キャプチャとラボ | 45 分 | ここも新しい信号は出てきません。信号の見方を 2 つ扱います。キャプチャ、フィルタ、Wireshark のラダー図に 20 分、ラボと、ラボがラダー図を組み立てる方法に 15 分、振り返りと、すでにあるキャプチャでフィルタを試すのに 10 分を使います。これより先の回は、どれもキャプチャを開き、多くはラボも開きます。 |
| 4. 登録 | 60 分 | 200 OK までに 35 分を使い、「ここまでで登録は完了」で休憩か質問に 5 分を取ります。残りで購読、登録の解除、失敗を見ます。動かす代わりに、CI の成果物 `registration-capture` のキャプチャを使えます。 |
| 5. 通話 | 60 分 | INVITE が UE 2 に届くまで（「6 と 7」のスライドのあたり）に 30 分、応答から切断までに 20 分、残りを失敗と振り返りに使います。端末を 2 つ開くのが面倒な人は、ラボから UE を動かせます。 |
| 6. SMS | 75 分 | 2 回に分けても構いません。そのときは「13 から 15。status report」のあと、45 分ほどで 1 回目を終え、2 回目を「ボディを読む」から始めます。ボディを手で読むのは 10 分の演習です。6 通の MESSAGE の表を印刷して配ると、キャプチャの中で迷いません。CI の成果物 `sms-capture` に、キャプチャとフレームの一覧があります。登録と通話の回が先です。Path、Service-Route、LIR は説明し直しません。 |
| 7. 補足サービス | 80 分 | 前半で AS のしくみと設定の置き場所を、後半でキャプチャをサービスごとに読みます。2 回に分けるなら「キャプチャを開く」の前で分けます。通話と SMS の回が先です。INVITE、PRACK、ACK と iFC の読み方は説明し直しません。CI の成果物 `mmtel-capture` に、キャプチャとフレームの一覧があります。 |

## ビルドする

要るのは Go だけです。版は [go.mod](../go.mod) にあり、`GOTOOLCHAIN=auto` を付ければ古い Go がその版を取ってきます。Node、ブラウザ、フォント、LibreOffice は要りません。このディレクトリで実行します。

```sh
GOTOOLCHAIN=auto go run ./cmd/slides check   # すべてのデッキを確かめる
GOTOOLCHAIN=auto go run ./cmd/slides build   # 確かめてから dist/ に書く
```

ホストに Go が無ければ、リポジトリのほかの部分と同じコンテナで、リポジトリのルートから実行します。

```sh
MSYS_NO_PATHCONV=1 docker run --rm -v "$PWD:/src" -v ims-practice-gomod:/go/pkg/mod \
  -w /src/slides golang:1.27.4-alpine go run ./cmd/slides build
```

`build` は `dist/ja/` と `dist/en/` に、デッキごとに `.pptx` と `.html` を 1 つずつ書きます。確かめる段階で問題が見つかれば、何も書きません。`dist/` は Git の対象外です。出力はソースだけで決まるので、2 回ビルドしても同じファイルになります。

手順書へのリンクは相対パスなので、チェックアウトした中の `dist/` から開いたファイルで使えます。CI の成果物のように、ファイルをほかの場所へ持ち出すときは、リポジトリのツリーのアドレスを渡します。リンクが絶対パスになります。

```sh
go run ./cmd/slides -repo-url https://github.com/<owner>/<repository>/blob/<commit> build
```

## pptx の中身

pptx は普通の PowerPoint のファイルです。スライドの上のものは、どれも編集できる PowerPoint の部品です。

| スライドの上 | pptx の中 |
| --- | --- |
| タイトル、副題、フッター、スライド番号 | スライドのレイアウト「Title Slide」「Section Header」「Title Only」のプレースホルダー。タイトルは PowerPoint のアウトラインに出ます。 |
| 段落、箇条書き、引用 | テキストボックス。箇条書きの記号は段落の箇条書き、番号は自動の段落番号です。 |
| 表 | 表（`a:tbl`）。見出しの行があります。 |
| コードのブロック | 灰色の地に等幅のフォントで書いたテキストボックス。 |
| ラダー図 | 図形のグループ 1 つ。参加者ごとの箱と線、メッセージごとの矢印（矢じりの付いたコネクタ）とテキストボックス、注記ごとの箱です。一部を直すときはグループを解除します。 |
| 手順書へのリンク | ハイパーリンク。パッケージはアドレスを URI として持つので、日本語のアンカーはパーセント符号化します（`%E7%99%BB...`）。 |

画像は 1 枚もありません。発表者ノートもありません。

分かっている制約。

- pptx はフォントの名前を書いています。ラテン文字は Calibri、日本語は Yu Gothic、コードは Consolas です。どれかが無いマシンでは別のフォントに置き換わり、文字の幅が少し変わります。
- 生成器は文字の幅を Arial の幅で測ります。Arial は Calibri や多くの日本語のフォントのラテン文字より広いので、普通の幅のフォントなら行は収まります。その代わり、表の行が文字に必要な高さより少し高くなることがあります。
- 収めるために文字を小さくしたスライド（「確かめる」を参照）は、pptx でもその大きさのままです。PowerPoint で箱に文字を足しても、下の箱は動きません。

## HTML

デッキごとにファイル 1 つで、ディスクから開けます。ネットワークからは何も読みません。スライドを 1 枚ずつ、ウインドウの大きさに合わせて出します。

| キー | 動き |
| --- | --- |
| →、↓、Page Down、Space、Enter | 次のスライド |
| ←、↑、Page Up、Backspace | 前のスライド |
| Home、End | 最初、最後のスライド |
| `f` | 全画面 |

アドレスにスライドの番号（`#12`）が残るので、リンクや再読み込みで同じスライドが開きます。印刷すると、pptx のスライドと同じ 10 × 5.625 インチの紙に 1 枚ずつ出ます。印刷の画面の「PDF に保存」で PDF になります。

アドレスの最後に `?check` を付けると（`04-registration.html?check`）、すべてのスライドを並べ、ブラウザが箱より大きく描いた文字のある箱を、ページの下に一覧で出します。ビルドの測り方が、本物のブラウザのフォントでも合っているかを確かめられます。

[check-html.js](check-html.js) は、これをすべてのデッキについて、画面なしの Chromium で行います。`build` のあとに、このディレクトリで実行します。

```sh
node check-html.js   # dist/ を読む
```

デッキごとに、はみ出した箱の数と、文字を描いたフォントを出します。箱が 1 つでもはみ出したときと、デッキの字形の 1% より多くを、デッキが名前を挙げていないフォントが描いたときに失敗します。デッキのフォントが無いマシンではそうなり、そこで測っても何も分からないためです。「⊕」のように、どのフォントにも無い記号は、どのマシンでも別のフォントで描かれますが、この割合には届きません。Node と Playwright、その Chromium と、フォントが要ります。Ubuntu では、パッケージ `fonts-crosextra-carlito`（Calibri と同じ幅の Carlito）、`fonts-noto-cjk`（Noto Sans CJK JP）、`fonts-dejavu-core`（DejaVu Sans Mono）です。

## 確かめる

`go run ./cmd/slides check` は、次のものを報告します。

- ソースの誤りと、その行。知らないブロック、セルの数が合わない表の行、HTML のコメントなどです。
- 文字を 80% まで小さくしても中身が収まらないスライド。黙って切ったり、さらに縮めたりはしません。スライドを分けるか、短くします。
- 存在しないファイルへのリンクと、手順書のもう無い見出しへのリンク。デッキは手順書の各手順に見出しでリンクしているので、見出しの名前を変えるとリンクが切れます。
- 片方の言語にしか無いデッキと、2 つの言語でスライドの数かレイアウトが違うデッキ。
- リポジトリが受け付けないコマンド。`sh` のブロックと行の中のコードを読みます。`docker compose` は `compose.yaml`（`-f` があればそのファイル）のサービスとプロファイルと照らします。`ue` は、`docker compose run` の中のものも含めて、`ue register -h` が出すサブコマンドと、サブコマンドごとに `ue サブコマンド -h` が出すフラグと照らします。ラボへの `curl` は、メソッドとパスを `internal/lab` が登録する経路と照らします。経路はそのソースから読みます。`scripts/` の下のパスは、ファイルがあるかを確かめます。ほかのアドレスへの `curl` は、そのアドレスとパッケージを [internal/facts/routes.go](internal/facts/routes.go) の `httpHosts` に足すまで失敗します。

デッキごとに、収めるために文字を小さくしたスライドと、その割合も出します。`ue` のフラグを読むために、リポジトリのルートで `./cmd/ue` をビルドして実行します。そのため、Go がビルドするぶん確認に時間がかかります。

リポジトリのルートで `go test ./...` を実行すると、同じ確認がデッキに対して走ります（`cmd/slides` の試験 `TestDecks`）。だから CI でも同じ確認で失敗します。`internal/pptx` の試験も、すべてのデッキを組み立てて、パッケージの部品を 1 つずつ確かめます。確かめるのは 2 つです。1 つは、どの部品にもコンテンツの型があり、どの関係にも行き先の部品があることです。もう 1 つは、生成器が書く要素ごとに、子の順番と、なければならない子と属性が、ECMA-376 のスキーマがその型に定めるとおりになっていることです。リポジトリのルートの `python3 scripts/check_links.py` は、デッキを含むリポジトリのすべての Markdown のリンクを確かめます。

## デッキを書く

デッキは、リポジトリの中では Markdown のように読めるテキストファイルです。書式はわざと小さくしてあります。ブロックの種類はいくつかだけで、既定のレイアウトが合わないときにレイアウトの行を書きます。

````markdown
---
title: UE が IMS に登録する流れ
footer: ims-practice 勉強会 4. 登録
lang: ja
---

# UE が IMS に登録する流れ

ims-practice 勉強会 第 4 回（SIP Digest での登録）

---

## 全体の形

```ladder
UE, P-CSCF, I-CSCF, S-CSCF, HSS
UE -> P-CSCF -> I-CSCF: REGISTER // 1 - 2
I-CSCF <-> HSS: UAR, UAA // 3
UE <-- P-CSCF <-- I-CSCF <-- S-CSCF: 401 // 6
```

- 1 回目は「誰か」を伝え、2 回目で「本人であること」を証明します。

---

[layout: exercise]

## 振り返り

1. REGISTER が 2 回送られるのは、なぜですか。
````

- **フロントマター。** ファイルは 2 つの `---` の行で挟んだ `title`（デッキの名前）、`footer`（各スライドの下に出す文字）、`lang`（`en` か `ja`。ディレクトリと同じ）で始めます。ほかのキーは書けません。
- **スライド。** `---` の行でスライドが終わります。スライドは見出しで始めます。`#` は最初のスライド（表紙）と、勉強会の部の始まりのスライドに使い、ほかのスライドは `##` にします。表紙と部の始まりのスライドには段落だけを書き、それが副題になります。
- **レイアウト。** 見出しの前の `[layout: 名前]` の行で、`content` 以外のレイアウトを選びます。`two-columns` のスライドでは、2 つの列の間に `[column]` の行を 1 つ置きます。
- **コメントは書かない。** HTML のコメント `<!-- ... -->` は誤りになります。デッキに発表者ノートはありません。会場への問いは答えと一緒にそのスライドに、演習の答えはそのあとの `answers` のスライドに、時間の目安は上の「勉強会の進め方」に書きます。

### ブロック

| ブロック | 書き方 | スライドでは |
| --- | --- | --- |
| 段落 | 文字の行。ソースの改行がスライドでも改行になります。 | 文字 |
| 箇条書き | 記号は `- `、番号は `1. `。入れ子は 2 つの空白で字下げし、1 段までです。記号の無い字下げの行は、すぐ上の項目の続きです。 | 箇条書きの記号か、自動の番号 |
| 表 | `\| a \| b \|` の行と、見出しの行のあとの区切りの行 `\| --- \| ---: \|`。セルの中の `\|` は `\\|` と書きます。 | 幅いっぱいの表 |
| コード | ` ``` ` で囲むブロック。`sh` や `go` のような語を付けます。タブは空白 4 つになります。 | 折り返さない等幅の文字。幅の広いブロックは文字を小さくします |
| ラダー図 | ` ```ladder ` で囲むブロック。下を見てください。 | 図形 |
| 引用 | `> ` で始まる行。デッキでは手順書を指すのに使います。 | 左に線の付いた小さな灰色の文字 |

行の中では、`**太字**`、`` `コード` ``、`[文字](https://example.org/)`、`<https://example.org/>` を使えます。記号の前にバックスラッシュを置くと、ただの文字になります。

### ラダー図

最初の行に、参加者を左から順にコンマで区切って書きます。ほかの行は 1 行が 1 段です。

| 段 | 描き方 |
| --- | --- |
| `A -> B: ラベル` | A から B への要求。実線の矢印で、上にラベルを置きます |
| `A --> B: ラベル` | 応答。破線の矢印です |
| `B <- A: ラベル`、`B <-- A: ラベル` | 同じものを右から左へ書いたもの |
| `A -> B -> C: ラベル` | B を通る 1 つのメッセージ。区間ごとに矢印を描きます。1 段の参加者は、左から右か右から左の順に並べます |
| `A <-> B: ラベル` | Diameter の組のような要求と応答。両端に矢じりのある矢印 1 本です |
| `note A, C: 文字` | A から C までの参加者にまたがる箱（1 人なら `note A: 文字`） |
| `... // 注` | 注は右の列に出ます。手順書の手順の番号などに使います |

ラベルはただの文字です。ラベルが図より広い段や、名前が列より広い参加者は、確かめる段階で誤りになります。

### レイアウト

| レイアウト | 選び方 | 中身 |
| --- | --- | --- |
| `title` | 最初のスライドの `#` | 勉強会の題、短い線、副題。左にアクセントの色の帯があります。 |
| `section` | 2 枚目以降の `#` | 勉強会の部の始まり。アクセントの色の地に白い文字です。 |
| `content` | `##`。既定 | 下に線の付いたタイトルと、上から順に並べたブロック。表、コード、ラダー図は幅いっぱいに広げます。 |
| `two-columns` | `[layout: two-columns]` | content と同じで、ブロックを同じ幅の 2 つの列に並べます。 |
| `exercise` | `[layout: exercise]` | 黄土色の content のスライドで、「演習」の札が付きます。演習と「振り返り」に使います。 |
| `answers` | `[layout: answers]` | 緑の content のスライドで、「解答」の札が付きます。演習のすぐあとに置きます。 |
| `summary` | `[layout: summary]` | ブロックを薄い色の板の上に並べます。「この回で分かること」に使います。 |

どのスライドも左下にデッキのフッターがあり、最初のスライドのほかは右下に番号があります。中身が高すぎるスライドは文字を 80% まで小さくし、それでも収まらなければ確かめる段階で誤りになります。

### デッキを足す

1. 2 つの言語のデッキを同じコミットで書きます。`decks/ja/NN-name.md` と `decks/en/NN-name.md` に、同じスライドを同じレイアウトで同じ順に並べます。今あるデッキのフロントマターを写して、`title` と `footer` を変えます。
2. 手順書へは、デッキからの相対パスでリンクします。たとえば `../../../docs/guide/ja/call.md#3-s-cscf-が番号を-sip-uri-に変える` です。手順書のラダー図を丸ごと写さないでください。全体がどこにあるかを書いたうえでなら、縮めた図は構いません。
3. 条項番号は、手順書がその手順に挙げているものだけを、手順書と同じ版で書きます。電話番号は手順書と同じ架空の番号（+1 202 555 01xx）を使います。
4. コードの抜き出しは、リポジトリのコードから数行をそのまま写し、ブロックのすぐ上にファイルへのリンクを置きます。コードが変わったら、抜き出しも確かめ直します。
5. `go run ./cmd/slides build` と `python3 scripts/check_links.py` を実行し、HTML と pptx を開いてスライドを見ます。

### 見た目を変える、レイアウトを足す

見た目は [internal/layout/theme.go](internal/layout/theme.go) にあります。色、フォント、文字の大きさ、content のスライドの枠です。2 つの出力も pptx のテーマも、ここから値を取ります。

レイアウトを足すときは、次の 4 か所を変えます。

1. [internal/deck/deck.go](internal/deck/deck.go) の `Layouts` に名前を足す。
2. [internal/layout/layout.go](internal/layout/layout.go) の `Slide` に箱の置き方を書き、`layout_test.go` に試験を足す。
3. [internal/pptx/slide.go](internal/pptx/slide.go) の `layoutOf` で、使う pptx のスライドのレイアウトを決める（表紙、部の始まり、そのほかのスライドに 1 つずつあります）。
4. 上のレイアウトの表に、2 つの言語で行を足す。

HTML は変えなくて済みます。レイアウトが置いた箱を、そのまま描くからです。
