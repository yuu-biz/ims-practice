# H.248（Megaco）

[English](README.md)

このパッケージは、H.248 のメッセージを ITU-T H.248.1 Annex B のテキストの符号化で読み書きし、Annex D.1 の手順で UDP の上のトランザクションを運びます。パッケージ `mediactl` は、3GPP の 2 つの H.248 のプロファイルについて、両側を持ちます。IMS-ALG と IMS-AGW の間の Iq（TS 29.334）と、MRFC と MRFP の間の Mp（TS 29.333）です。

このプロジェクトのノードは、どれもこのパッケージを使っていません。P-CSCF、IBCF、MRFC は、H.248 ではなく、メディアの中継ノードの HTTP の制御 API（`internal/agw`）で中継ノードを動かします。ここの試験と例は、コントローラとゲートウェイを UDP で向かい合わせて動かします。H.248 のメッセージを読んだり、キャプチャしたりできます。

```sh
go test ./internal/h248/...
go doc ./internal/h248
go doc ./internal/h248/mediactl
```

型の説明と、従っている条項は、パッケージのコメント（`doc.go` と `mediactl/doc.go`）にあります。

## このパッケージで簡略化していること

どの行の場所にも、コードに `SIMPLIFIED:` のコメントがあります。ここでの H.248.1 は、3 つのプロファイルが参照している 2002 年 5 月の版と、その Corrigendum 1 です。

| 場所 | 省いたこと | 理由 |
| --- | --- | --- |
| `IndAuditParameter`、H.248.1 Annex B.2（indAudterminationAudit） | LocalControl、Events、Signals、Statistics、Packages の各記述子の項目を、1 つずつ監査すること。1 つずつ監査できるのは、TerminationState 記述子の項目だけです。 | Iq と Ix はどれも監査せず、Mp が監査するのは LocalControl の任意の性質 1 つだけです（TS 29.333 5.8.5）。記述子をまるごと監査することは、`AuditToken` でできます。 |
| `Endpoint`、TS 29.334 5.12、TS 29.238 5.12、TS 29.333 5.12 | SCTP。Endpoint は H.248 を UDP でしか運ばないので、SCTP のときに Annex D.1 の一部に代わる H.248.4 の部分もありません。 | Go の標準ライブラリに SCTP が無いためです。3 つのプロファイルは、どれも UDP を選べるようにしています。 |
| `Timers`、H.248.1 Annex E.2.1 | ROOT の終端への Modify で、4 つのタイマーを変えること。Endpoint は作ったときの値を使い続けます。 | 値を変える Modify には、その Modify を扱う側が新しい Endpoint を作る必要があります。 |
| `Controller`、TS 29.334 5.17.2.6 | `TerminationHeartbeat` が nil のときに、P-CSCF が見失ったコンテキストを解放すること。すべてのコンテキストを使用中とみなすので、ゲートウェイに残ります。 | どのコンテキストを今も使っているかは、コントローラを呼ぶ側しか知らないためです。 |
| `Controller`、TS 29.334 5.17.3.19 | ContextID が ALL か、終端がワイルドカードの報告で、サービスを外れた終端のコンテキストを片付けること。Mp でワイルドカードの場合も同じです。コントローラは、報告が名指ししたコンテキストは片付けますが、これらでは何も片付けません。 | コントローラは、ゲートウェイのコンテキストと終端の一覧を持っていないためです。 |
| `Controller`、H.248.1 7.2.8 | Disconnected の ServiceChange のあとに、ゲートウェイを監査すること。 | この条項は監査してよいとしているだけで、求めてはいません。 |
| Mp の `Controller`、H.248.1 6.1.2 | 最後の終端を外したときに、コンテキストも一緒に消えたことを `SubtractTermination` の呼び出し元に伝えること。コントローラはいつも「消えていない」と答えます。MRFC は、そのコンテキストへの次の `AddTermination` が `agw.ErrNoContext` で失敗したときに、コンテキストが消えたことを知ります。 | Subtract の応答は、コンテキストが消えたかを伝えません。また、コントローラはゲートウェイのコンテキストと終端を記録しません。複数のコントローラを並べて動かせるようにするためです。 |
| `Controller`、TS 29.334 5.17.2.7 | 解放された bearer の報告を、コントローラの呼び出し元に渡すこと。コントローラは条項のとおり Notify に応答し、イベントはログに書くだけです。 | コントローラの Add、Modify、Subtract には、セッションを持つ呼び出し元に伝える手段が無いためです。 |
| Local 記述子と Remote 記述子、H.248.1 7.1.8 | ゲートウェイが選ぶための候補。1 つの記述子に複数のセッション記述を入れるものと、1 つの欄に複数の値を入れるものです。どちらも拒否します。 | このプロジェクトのコントローラは候補を 1 つしか出さないためです。 |
| `Gateway`、H.248.1 11.2、11.5 | コントローラが答えないときに、予備のコントローラの一覧を順に試すこと。ゲートウェイには 1 つのコントローラだけを設定し、失敗したあとはそこから始め直します。応答の ServiceChangeMgcId には従います。 | 11.2 は、予備のコントローラの一覧を任意としているためです。 |
| `Gateway`、TS 29.334 5.17.2.7 | g/cause で bearer の解放を報告すること。イベントは受け付けますが、報告はしません。 | 中継ノードは Subtract までコンテキストのポートを持ち続けるので、それより前に bearer が解放されることは無いためです。 |
| `Gateway`、H.248.37 6.6 | コントローラが ipnapt/latch を送ったときだけラッチすることと、TS 29.334 がゲートウェイに求めるモード OFF と RELATCH（Table 5.14.3.12.1）。OFF と RELATCH は拒否します。中継ノードは、信号があってもなくても、最初に受けたパケットですべての終端をラッチします。 | `Relay` には、終端ごとにモードを決める方法が無いためです。 |
| `Gateway`、TS 29.334 5.8.5 | 監査で ROOT の性質（root/*）を返すこと。 | 値は Endpoint のタイマーで、事前に設定されるものだからです（TS 29.334 5.14.3.2）。 |
| `Gateway`、TS 29.334 5.17.3.7 | IMS-ALG Ordered Re-register。ゲートウェイを別のコントローラに移す Handoff です。エラー 501 で拒否します。 | このプロジェクトのコントローラは送らないためです。 |
| `Gateway`、TS 29.334 5.5、5.17.2.2 | 緊急呼の印や優先度の付いたコンテキストを、ほかと違うように扱うこと。属性は受け付けますが、効果はありません。 | 中継ノードは、すべてのコンテキストを同じように扱うためです。 |
| `Gateway`、TS 29.334 5.17.2.5、5.17.3.10 | Subtract と AuditValue のコンテキスト ID の ALL。エラー 501 で拒否します。 | ゲートウェイのすべてのコンテキストをたどることになるためです。このプロジェクトのコントローラは、コンテキストを 1 つずつ指定します。 |
| `Gateway`、H.248.1 | コンテキストに終端を 1 つずつ Add すること。2 つの Add は、コンテキストを作るアクションにそろって入っている必要があり、あとからの Add はエラー 434 で拒否します。 | 中継ノードは、コンテキストを 2 つの終端と一緒に一度に作るためです。 |
| `Gateway`、TS 29.334 5.17.3.10 | コンテキストの終端を監査すること。 | このプロジェクトのコントローラが監査するのは ROOT だけだからです。 |
| `Gateway`、TS 29.334 5.17.2.3 | Modify の Local 記述子で、終端のローカルの資源を変えること。 | 中継ノードは、選んだポートを通話のあいだ変えないためです。 |
| `Gateway`、TS 29.334 5.17.2.5 | 終端を 1 つずつ Subtract すること。ゲートウェイは、両方を Subtract するワイルドカード `*` を求めます。 | 中継ノードは、コンテキストをまとめて解放するためです。 |
| Mp の `Gateway`、TS 29.333 5.7.8 | トポロジーの isolate、oneway、bothway。エラー 522 で拒否します。 | メディアノードは、どの終端にもほかのすべての終端のメディアを送ります。これは H.248.1 7.1.18 の既定のトポロジーで、ほかのトポロジーはありません。 |
| Mp の `Gateway`、TS 29.333 5.5 | MPS の優先度の付いたコンテキストを、ほかと違うように扱うこと。属性は受け付けますが、効果はありません。 | メディアノードは、すべてのコンテキストを同じように扱うためです。 |
| Mp の `Gateway`、TS 29.333 5.17.3.8 | AuditValue のコンテキスト ID の ALL。エラー 501 で拒否します。 | ゲートウェイのすべてのコンテキストをたどることになるためです。 |
| Mp の `Gateway`、TS 29.333 5.8.4、5.8.5 | Move と、終端の信号、イベント、統計の AuditValue。 | このプロジェクトの MRFC は、どちらも使わないためです。 |
| Mp の `Gateway`、H.248.1 7.2.3 | 終端をワイルドカードで指定する Subtract。 | Release IMS Termination は終端を 1 つだけ指定し、このプロジェクトの MRFC も同じだからです。 |
| Mp の `Gateway`、TS 29.333 5.17.2.3 | Modify の Local 記述子で、終端のローカルの資源を変えること。 | メディアノードは、終端が Subtract されるまで、選んだポートを変えないためです。 |
| Mp の `Gateway`、TS 29.333 5.17.2.9、5.7.4 | 信号のリストと、信号の KeepActive。どちらも拒否します。 | メディアノードはアナウンスを 1 つずつ再生し、Signals 記述子を受けるたびに初めから再生し直すためです。 |
| Mp の `Gateway`、H.248.7 4.5 | アナウンスごとに事前に設定する、繰り返しの回数と長さ。メディアノードは制限なしで 1 回だけ再生します。変種（av）は拒否し、向きは external だけを受け付けます。 | メディアノードにはアナウンスの事前の設定が無く、終端の相手の側にしか再生しないためです。 |
| Mp の `Gateway`、H.248.1 7.1.11、E.1.2 | 新しい Signals 記述子で止まった信号（SD）と、ほかの理由で止まった信号（NC）を報告すること。報告するのは、TO と、heartbeat で止まったアナウンスの EV だけです。 | このプロジェクトの MRFC がアナウンスを止めるのは、終端を Subtract するときだけだからです。 |
| `MpProfile`、H.248.9 6.2.5.1.2 | セグメントのリスト、変数、ほかのホストにあるセグメントでできたアナウンス。どれも拒否します。 | このプロジェクトの MRFP は、事前に設定したアナウンスを 1 つずつ再生するためです。 |
| `Endpoint`、H.248.1 Annex D.1.3 | 応答にかかった時間から再送のタイマーを見積もること。附属書は、ふつうはそうするのがよいとし、その方法の 1 つとして TCP の AAD と ADEV を注に挙げています。どの要求も、設定で決める `InitialRetransmissionTimer` から始め、ADEV は 0 とみなします。 | 測るには、トランザクションより長く残る相手ごとの状態が要り、Endpoint はトランザクションの間の状態しか持たないためです。 |
| `Endpoint`、H.248.1 Annex D.1.2.2 | 同じ相手への次の要求など、どのメッセージにでも、ほかの応答の確認を載せること。確認するのは、Pending のあとの応答と、ImmAckRequired の付いた応答だけです。 | 相手はほかの応答を LONG-TIMER まで覚えておくだけです。メモリは使いますが、手順は変わりません。 |
| パーサ、H.248.1 Annex B.2（parmValue、alternativeValue） | 候補 `{a, b}`、範囲 `[a:b]`、関係 `<`、`>`、`#`。 | どれもコントローラが値の候補を出すためのものです。3 つのプロファイルは、候補を Local 記述子の SDP で渡します（TS 29.334 5.17.2.2）。 |
