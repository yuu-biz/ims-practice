# Jex の式

[English](README.md)

このパッケージは、TS 32.161 の Jex の式を読んで評価します。3GPP の管理のサービスでは、要求や購読が何を対象にするかを Jex の式で書きます。扱うのは Jex conditions のプロファイル（TS 32.161 7.6）で、文法は A.4 にあります。JSON の文書をたどる経路、比べる式、`and`、`or`、`not()`、括弧、`contains()` です。通知の購読の `notificationFilter` がこの式で、通知ごとに評価します。警報の一覧の読み出しでは、TS 28.111 A.1.4 の形で警報の記録を選びます。`/AlarmList[id="1"]/attributes/alarmRecords/*[perceivedSeverity="CRITICAL"]` のような `filter` か `dataNodeSelector` と、記録を id で名指しする `fields` です。

文法に合わない式は構文の誤りです。文法には合っていても、このパッケージが評価しないものを求める式と、4096 バイトより長い式、64 段より深く入れ子にした式は、扱えない式です。TS 32.158 6.6.5.2 では、前者に 400、後者に 500 で答えます。何を評価するかは、パッケージのコメントにあります。

```sh
go test ./internal/jex
go doc ./internal/jex
```

## このパッケージで簡略化していること

どの行の場所にも、コードに `SIMPLIFIED:` のコメントがあります。

| 場所 | 省いたこと | 理由 |
| --- | --- | --- |
| パッケージ `jex`、TS 32.161 7.5、A.4 | `[0]` のように位置を書く述語。JSON の配列の要素を選びます。この述語を含む式は、扱えない式です。 | ここで評価する文書は通知と警報の一覧で、警報の記録は id を鍵にした JSON のオブジェクトなので、この述語を要る式がありません。 |
