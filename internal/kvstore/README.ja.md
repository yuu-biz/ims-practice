# ノードの外の Store

[English](README.md)

パッケージ `kvstore` は、キーで引く項目をノードの外に置く Store です。ノードの状態がプロセスと一緒に消えないように、また、1 つの役割の複数のインスタンスが状態を分け合えるようにするためです。障害のあとに入れ替わったノードは、前のノードの登録と通話を引き継ぎます。`MemoryStore` は項目をプロセスの中に、`Valkey` は Valkey のサーバーに置きます。その下のパッケージは、それぞれ 1 つの役割の Store です。たとえば `scscfstore` は S-CSCF の Store です。`kvlock` は、役割のインスタンスが分け合う、利用者ごとのロックです。

```sh
go test ./internal/kvstore/...
go doc ./internal/kvstore
```

## これらのパッケージで簡略化していること

どの行の場所にも、コードに `SIMPLIFIED:` のコメントがあります。

| 場所 | 省いたこと | 理由 |
| --- | --- | --- |
| `NewValkey`、1 つのアドレス | TLS と `AUTH`（Valkey の利用者と ACL）、引き継ぐレプリカを見つける仕組み（Sentinel、クラスタ）。サーバーには 1 つのアドレスでつなぎます。 | Store はノードのプライベートなネットワークの中にあります。Diameter や SIP と同じく、キャプチャを読めるように、既定では暗号化しません。Store は 1 台のサーバーなので、単一障害点です。このプロジェクトが見せるのは IMS のノードの冗長構成で、Store の冗長構成ではありません。 |
| `kvlock.Locker.Lock`、フェンシングのトークンが無いこと | ロックを持って書くときに、フェンシングのトークンを付けません。リースより長く止まってから動き出した持ち主は、次の持ち主が書いたものを上書きすることがあります。 | フェンシングをするには、ロックの版を、役割の Store へのすべての書き込みの条件にする必要があります。そういう条件を受け付ける役割の Store はありません。リースは、ロックを持ってする作業のうち最も長いものより長くしてあります。 |
| `mmtelstore`、TS 24.147 5.3.2.7 | 会議のフォーカスを受け持つインスタンスが止まると、参加者を外すことも、会議の URI を手放すことも、誰もしません。記録は Store に残ります。 | 会議のダイアログは、そのインスタンスのプロセスの中にありました。ほかのインスタンスは、別のインスタンスが受け持った会議を続けません。BYE をどのインスタンスも受けなかった通話の記録も、同じように残ります。 |
